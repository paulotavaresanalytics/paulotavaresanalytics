## Sobre mim

Sou **Analista de Dados**: construo dashboards, acompanho KPIs e apoio decisões estratégicas em ambientes orientados por metas, trabalhando com dados em ERPs, pipelines e automações.

Analisando dados todos os dias, percebi que o maior problema raramente está no dashboard — está no dado que chega atrasado, duplicado ou inconsistente. Foi isso que me levou à **Engenharia de Dados**: quero atuar na origem, garantindo que o dado chegue confiável a quem decide.

- 📊 **Base:** análise exploratória, KPIs de negócio, estatística descritiva e visualização
- 🔄 **Transição:** ingestão, tratamento e qualidade de dados, streaming com Kafka, ambientes com Docker
- 💼 **Diferencial:** conheço a ponta do negócio — sei quais perguntas o dado precisa responder antes de desenhar o pipeline

## 🏗️ Engenharia de Dados

### [Dashboard de clima em tempo real](https://github.com/paulotavaresanalytics/dashboard_de_clima_tempo_real) · 🚧 em construção
Pipeline de **streaming**: um *producer* em Python coleta dados climáticos de uma API pública e publica em um tópico Kafka; um *consumer* lê o fluxo e atualiza um dashboard em tempo real.

`Python` `Apache Kafka (KRaft)` `confluent-kafka` `Docker Compose`

### [Mini-ETL: análise da base Varejo](https://github.com/paulotavaresanalytics/Miniprojeto_PauloGomes_AnaliseDeDados_T6)
Extração via API do Kaggle, transformação de tipos, tratamento de nulos "disfarçados" (`#N/D`), remoção de duplicatas e carga de um dataset limpo pronto para consumo. O README documenta **cada decisão de qualidade de dados** e o raciocínio por trás dela.

`Python` `pandas` `kagglehub` `GitHub Codespaces`

**Próximos passos:** pipeline batch com carga em PostgreSQL · camadas staging → marts com **dbt** · orquestração
